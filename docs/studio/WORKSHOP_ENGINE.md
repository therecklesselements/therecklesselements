## Request handling

Every Studio request or material redirection starts with **RECKLESS ELEMENTS WORKSHOP PREFLIGHT**. The lead gives five fields before using tools, issuing commands, making edits or delegating.

| Field | What the creator should see |
| --- | --- |
| Objective | The specific result the creator asked for. |
| Approach | The proposed method and the practical improvement it offers. |
| Tools and resources | Which evidence, tools or capabilities the lead selected and why. |
| Orchestration | Who owns execution and which independent parts can run together. |
| Verification | An observable outcome capable of showing that the work succeeded or failed. |

The lead interprets the request, retrieves project context, researches gaps, analyzes and optimizes the approach, orchestrates capabilities, executes, verifies and preserves reusable findings. A direct question can use a single compact preflight. When a missing fact determines the route, the lead names the initial inspection and confirms the method before substantive work. Project rules govern model choice, permissions and acceptance. The creator judges game feel and release readiness.

## Implemented operating paths

- Scoped workstation instructions and a reusable Workshop skill put intake into ordinary Studio and project sessions. The Master Space carries the same mission and preflight in its Agent Instructions and playbook.
- A project-aware router proposes tools and evidence across 15 task families. The lead applies the request’s actual constraints and selects relevant HYPEROP and PStack procedures.
- Scripted jobs can use a tools-free local model to rank competing catalog routes before the signed-in stock Codex executor runs. The executor receives the full request and advisory plan. Supplied-evidence requests bypass local inference. The project lead determines feasibility.
- The learning register ties a scoped finding to a verification record. It deduplicates exact repeats and rechecks the evidence before suggesting reuse. The lead judges applicability and can update the owning workflow.
- Native submission and pre-tool hooks register per-turn intake and can reject missing or inconsistent receipts on supported clients and tools. Stock Codex requires local user trust to activate the commands. Receipt integrity and the visible assistant response have separate tests.
